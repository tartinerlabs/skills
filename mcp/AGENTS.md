# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## Commands

pnpm only (`pnpm-lock.yaml`, pnpm 12 and Node declared in `devEngines`). pnpm workspace with Turborepo (`turbo.json`): the Google Search Console server lives in `apps/gsc`, the PageSpeed Insights + Chrome UX Report server in `apps/pagespeed` (same structure, tools call Google with the server's `GOOGLE_API_KEY`), the IndexNow server in `apps/index-now` (no sign-in, database or Google API, and not hosted: a local stdio server (`serveStdio` in `src/index.ts`) published to npm as `@tartinerlabs/index-now-mcp` by semantic-release's `publishCmd` with npm trusted publishing, because IndexNow permanently rate-limits cloud egress IPs; `submit_urls` runs `runSubmission` (`src/indexnow/submission.ts`) in-process, checking the site's `<key>.txt` and retrying IndexNow on 5xx/network errors (429 fails fast) with progress notifications; it does not depend on `@repo/core` (private, unpublished) and logs to stderr, since stdout carries the protocol), the App Store Connect server in `apps/asc` (pagespeed's structure on Cloudflare Workers with D1: `src/lib/auth.ts` and `src/db/index.ts` read bindings from `cloudflare:workers` (typed by `worker-configuration.d.ts`, generated by `pnpm types` (`wrangler types`) and committed; rerun it after changing `wrangler.jsonc`; tests never import them), Better Auth with `provider: "sqlite"`; each user stores their own ASC API keys at `/keys` (`createKeyPages` from `@repo/core/keys`, hand-written `src/db/schema/keys.ts`), and `src/asc/client.ts` signs a fresh 2-minute ES256 JWT per request with the chosen key (`key_id` input when a user has several); deployed to Cloudflare Workers by git deployment from `wrangler.jsonc` on the Custom Domain `asc.mcp.tartinerlabs.com`, with Wrangler run locally only as `wrangler types`), provider-neutral auth/HTTP code shared by apps lives in `packages/core` (`@repo/core`, runs on Node and Workers: env is passed in (default `process.env`), the CIMD transport is injected (`@better-auth/cimd/node` on Node, `@repo/core/cimd` on Workers), no `node:` imports; compiled to `dist/` because Vercel does not compile workspace TypeScript; types resolve to `src/`), and Biome and semantic-release run from the root. Each app's `biome.json` and `turbo.json` extend the root ones (`"extends": "//"` / `["//"]`); declare an app's env vars in its own `turbo.json` (Turborepo runs in strict env mode). Paths and app commands below are relative to `apps/gsc` unless noted.

```sh
pnpm check                          # root: biome lint + turbo typecheck/test — what CI runs, plus `pnpm build`
pnpm test                           # root: turbo run test
pnpm format                         # root: biome format --write
pnpm build                          # root: turbo run build → apps/*/dist/
pnpm vitest run tests/tools.test.ts # single file
pnpm vitest run -t "search_analytics"  # single describe/test by name
pnpm db:push                        # sync schema to the Neon development branch
pnpm db:migrate                     # apply committed migrations (also runs as `vercel-build`)
```

Tests need no database, network or Google credentials: they drive `createServer` with a mocked `GscClient` (`tests/helpers.ts` → `mockClient`, `mcpRequest`, `createTestClient`) and never import `src/lib/auth.ts`.

## Architecture

A stateless Streamable HTTP MCP server for read-only Google Search Console access, deployed to Vercel as a single Hono function (`vercel.ts`: region `sin1`). TypeScript runs as native ESM with `.ts` import extensions (`rewriteRelativeImportExtensions`, `erasableSyntaxOnly` — no enums/namespaces/parameter properties).

Request flow:

1. `src/index.ts` — Hono app routing `/api/auth/*` and `/.well-known/*` to Better Auth, `POST /mcp` to `handleMcp`, and `/sign-in` + `/consent` to `src/pages.ts`.
2. `src/http.ts` — `createMcpEndpoint` from `packages/core/src/http.ts`: Origin validation (requests from web pages are refused), then `requireMcpAuth` from `@better-auth/mcp` verifies the JWT access token and maps claims to `AuthInfo` with `extra.userId = sub`, then `createMcpHandler` builds a fresh `McpServer` per request.
3. `src/server.ts` — `createServer(getClient)` registers `ping` plus one tool per file in `src/tools/`. Each `register*Tool(server, getClient)` takes a lazy `GscClientProvider` so credentials are resolved inside the tool call and auth failures surface as tool errors, not HTTP errors.
4. `src/google/client.ts` — `getUserGscClient(userId)` loads the user's Google account via Better Auth's internal adapter, checks the `webmasters.readonly` scope was actually granted, gets/refreshes the Google access token via `auth.api.getAccessToken`, and wraps `@googleapis/searchconsole` behind the narrow `GscClient` interface (the seam tests mock).

Auth (`src/lib/auth.ts` calls `createAuth` from `packages/core/src/auth.ts` with the app's scopes): Better Auth is the OAuth 2.1 authorisation server for MCP clients — Google as the only social provider (offline access, encrypted tokens), JWT plugin, `mcp` plugin (resource = `${BETTER_AUTH_URL}/mcp`), and CIMD (client ID metadata documents; dynamic client registration is off). `/sign-in` and `/consent` (`createPages` in `packages/core/src/pages.ts`) verify Better Auth's signed query and render minimal HTML with strict CSP.

Apple key building blocks for apps that sign requests with a user's own key (runtime-neutral, WebCrypto only, no `node:` imports; import as `@repo/core/signing` and `@repo/core/keys`): `packages/core/src/signing.ts` (`importP256PrivateKey` for a `.p8` PEM, `signEs256Jwt`) and `packages/core/src/keys.ts` (`encryptSecret`/`decryptSecret` on Better Auth's `secretConfig`, and `createKeyPages` — `keysPage` (`GET /keys`), `addKey` (`POST /keys`) and `removeKey` (`DELETE /keys/{id}`) over the app's own `KeyStore` table; strict CSP like `/sign-in`, and the writes additionally need a session and an `Origin` equal to the `BETTER_AUTH_URL` origin).

Tool conventions (follow when adding a tool):
- Zod 4 input schemas (`import * as z from "zod"`); shared ones such as `siteUrlSchema` live in `src/schemas/common.ts`.
- Annotate `readOnlyHint: true`; `tests/server.test.ts` asserts the exact tool list and that every tool is read-only. The one exception is `submit_sitemap`, registered only with `createServer(getClient, { allowWrite: true })` (`GSC_ENABLE_WRITE=true`, which also swaps the Google scope to `webmasters`).
- Return JSON as a text content block; wrap the body in `try/catch` and return `toToolError(toolName, error)`. `src/utils/errors.ts` classifies Google/Gaxios/network errors into `[invalid_input|auth|permission|quota|not_found|unavailable|network|unexpected]` messages. Throw `CredentialsError` for sign-in problems.
- Log only through `src/utils/logger.ts` (`createLogger` from `packages/core`: JSON lines on `console` with redaction of tokens/secrets/headers); never log tokens or put them in tool results.

## Database

Drizzle ORM 1.0 RC on Neon Postgres (`src/db/index.ts`, node-postgres, relations v2). `drizzle.config.ts` uses `DATABASE_URL_UNPOOLED` and `schemaFilter: ["public"]` (Neon Auth owns `neon_auth`).

- `src/db/schema/auth.ts` is generated by the Better Auth CLI (`pnpm auth:generate`, needs `BETTER_AUTH_URL`) and `drizzle/` is generated by Drizzle Kit. Never hand-edit either; both are excluded from Biome.
- Neon `development` branch: iterate with `pnpm db:push`. `production` branch: schema changes only via committed migrations. Do not run `pnpm db:generate` unless explicitly asked.
- `apps/asc` is on D1 (`drizzle-orm/d1`, `dialect: "sqlite"`, `driver: "d1-http"` with `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_D1_DATABASE_ID` and `CLOUDFLARE_API_TOKEN`); D1 rejects `BEGIN`, so Better Auth runs without transactions. Iterate with `pnpm db:push` against a separate development D1 database (`CLOUDFLARE_D1_DATABASE_ID` set to its ID, never production's); production gets schema changes only via committed migrations. Its migrations live in `drizzle/`; `wrangler.jsonc` points `migrations_dir`/`migrations_pattern` at Drizzle's `drizzle/*/migration.sql` layout.

## Environment

Required: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (must exactly match the URL clients use for `/mcp`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Optional: `GSC_ENABLE_WRITE` (`apps/gsc` only), `LOG_LEVEL`. `apps/pagespeed` also requires `GOOGLE_API_KEY` (PageSpeed Insights API and Chrome UX Report API enabled), sent as the `x-goog-api-key` header. `apps/asc` needs no `DATABASE_URL` (D1 binding `DB`) and no server-held Apple key; `BETTER_AUTH_URL` and `LOG_LEVEL` are plain vars and the other three are secrets, all set under the Worker's Variables and Secrets (`keep_vars` keeps them across deploys), and `wrangler.jsonc` binds `DB` without a database ID (provisioned on the first deploy). See README for Google Cloud and Vercel setup. Vercel Deployment Protection blocks the self-hosted JWKS fetch and OAuth flow on preview deployments.

## MCP elicitation and tasks

Spec reference: MCP 2026-07-28 (`modelcontextprotocol.io/specification/2026-07-28`). Client support varies (Claude clients included), so check the client's advertised capabilities and keep every tool working when they are absent.

- **Elicitation** (client capability `elicitation`): during a tool call the server sends `elicitation/create` to ask the user for input. Form mode (`mode: "form"` or omitted) sends `message` + `requestedSchema` (flat object of string/number/boolean/enum properties) and gets `content` back; URL mode (`mode: "url"`) sends `message` + `url` for out-of-band steps (OAuth, API keys, payments) and gets no data back. Responses are `accept` (submitted), `decline` (explicit no) or `cancel` (dismissed); handle each. Never request secrets via form mode. Candidate use: confirming `submit_sitemap` (`apps/gsc`) before writing.
- **Tasks** (extension `io.modelcontextprotocol/tasks`, negotiated under `capabilities.extensions` by both sides): the server returns a task handle instead of blocking; the client polls `tasks/get` for status/result and sends mid-flight input with `tasks/update` (no `tasks/result` or `tasks/list` in this revision; servers may return handles unsolicited). Candidate use: `submit_urls` (`apps/index-now`), which blocks for its retries (up to about 16 minutes waiting for the key file).
- Both need server-to-client messages or durable state across requests; our servers build a fresh `McpServer` per stateless Streamable HTTP request (Vercel, Workers), so confirm the round-trip works on the deployed runtime before relying on either.
