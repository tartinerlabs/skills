# Systems-Project Commit Messages

The area-prefix conventions of Git, the Linux kernel, and Chromium. The universal rules in `rules/message-format.md` still apply — this covers what these projects add on top.

These repositories are usually contributed to by patch or by a gated review system, and their rules are stricter than a typical GitHub project's. Apply this file when working in one of them or in a downstream that mirrors their style. See also `references/go.md`, which follows the same family with its own capitalisation rule.

## Git

```
doc: clarify distinction between sign-off and pgp-signing
githooks.txt: improve the intro section
refs: HEAD is also treated as a ref
```

- Structure: `area: description`, where `area` is a filename or general code area.
- Subject ~50 characters, **no full stop**.
- Only the first letter of the *area* may be capitalised; the first word after the colon is **lowercase** unless it is an acronym such as `HEAD`. `doc: Clarify …` and `githooks.txt: Improve …` are explicitly called out as wrong.
- Find the right area prefix by reading history on the files being changed: `git log --no-merges <files>`.
- Body must state the **problem** (present tense, without "Currently"), the **justification** for this solution, and any **alternatives considered**.
- Imperative mood: "make xyzzy do frotz", not "[This patch] makes xyzzy do frotz".
- `Signed-off-by:` is required — commit with `git commit -s`.
- Reference other commits as `Commit f86a374 (pack-bitmap.c: fix a memleak, 2015-03-30)`, generated by `git show -s --pretty=reference <commit>`.

## Linux Kernel

```
ext2: improve scalability of bitmap searching
x86: fix eflags tracking
```

- Structure: `subsystem: summary phrase`, where the subsystem identifies the area being patched.
- Summary **no more than 70–75 characters** — wider than the usual 50 — and it must convey both what the patch changes and why it is necessary.
- Imperative mood, as above.
- `Signed-off-by:` is mandatory under the Developer's Certificate of Origin.

## Chromium

- Short subject, blank line after it — treated as crucial, since git uses this shape for `git log --oneline` and similar tooling.
- Target ~60 characters including tags, 72 as a hard limit.
- Capitalise the first word after the final tag; no trailing period.
- Body wrapped at 72 columns.
- Bug references go in **footer tags**, not the subject:

```
Bug: 123456
Bug: skia:1234
Fixed: 123456
```

`Bug:` takes a comma-separated list and may be bare (defaulting to the chromium project) or project-qualified. `Fixed:` uses the same format and closes the bug when the change lands.

## Optional Credit Trailers

Git and the kernel share a vocabulary of trailers, capitalised on the first letter only (`Signed-off-by`, not `Signed-Off-By`):

`Reported-by:`, `Acked-by:`, `Reviewed-by:`, `Tested-by:`, `Co-authored-by:`, `Helped-by:`, `Mentored-by:`, `Suggested-by:`

Add these only when the information is actually known — from conversation context or the issue thread — never speculatively.
